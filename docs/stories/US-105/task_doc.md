# US-105: Project scaffold with typecheck, lint, test, build scripts
**Status:** Ready for UAT · **Category:** devops · **Points:** 2 · **Sprint:** —

## Summary
The repository now has a TypeScript project targeting Node.js 22 with standard check scripts (`typecheck`, `lint`, `test`, `build`). Every later story can be verified with these scripts. No end-user behaviour changes.

## What was built
- `package.json`: `type: module`, `engines.node: >=22`, scripts `typecheck`, `lint`, `test`, `build`, `start`; dev dependencies only.
- `package-lock.json`: generated by `npm install`.
- `tsconfig.json`: strict, `NodeNext` module resolution, ES2023 target, includes `src` and `test`.
- `tsconfig.build.json`: extends `tsconfig.json`, emits to `dist` from `src`.
- `eslint.config.js`: flat config with `@eslint/js` and `typescript-eslint` recommended rules; ignores `dist` and `node_modules`.
- `src/version.ts`: exports `VERSION = "0.1.0"`.
- `test/sample.test.ts`: one `node:test` case asserting `VERSION` is `"0.1.0"`.
- `.env.example`: `PORT=3000`, `DATA_FILE=data/kudos.json`.
- `.gitignore`: appended `.env`, `dist`, `data/kudos.json` (`node_modules/` was already present).

## How it works
- **AC 1, scripts:** `typecheck`, `lint`, `test` and `build` each exit 0 on the scaffold.
- **AC 2, Node version:** `engines.node` is `>=22`.
- **AC 3, git hygiene:** `.env`, `node_modules/`, `dist` and `data/kudos.json` are git-ignored.
- **AC 4, env example:** `.env.example` documents `PORT` and `DATA_FILE` with their defaults.

## How to test
Run from the repository root (Node 22):
1. `npm install`
2. `npm run typecheck`: exit 0
3. `npm run lint`: exit 0
4. `npm test`: one test passes
5. `npm run build`: writes `dist/version.js`, exit 0

Manual checks:
- AC 1: run the four scripts; all exit 0 on a clean checkout after `npm install`.
- AC 2: open `package.json`; `engines.node` is `>=22`.
- AC 3: open `.gitignore`; it lists `.env`, `node_modules/`, `dist`, `data/kudos.json`.
- AC 4: open `.env.example`; it contains `PORT=3000` and `DATA_FILE=data/kudos.json`.

## Deployment notes
- Run `npm install` once to create `node_modules` and the lock file.
- Copy `.env.example` to `.env` for local configuration. `.env` is never committed.
- No migrations, no external services, no CI workflow.

## Known limitations

- No CI workflow (out of scope).
